# 需求-AI股票分析功能完善-20260319 技术方案

## 1. 需求依据

基于 `feature/需求-AI股票分析功能完善-20260319.md`，核心目标是将 AIAnalysis 页面从静态模拟数据升级为真实 Agent 驱动的 AI 分析页面。

## 2. 功能范围

| 编号 | 功能 | 说明 |
|------|------|------|
| FR-01 | 接入真实 Agent 分析 | 调用 NewChatStream，Agent 利用工具生成真实分析，流式展示 |
| FR-02 | 扩展分析维度 | 新增行业对比、财报深度解读、研报摘要。注意：行业对比和研报摘要主要依赖 prompt 引导 LLM 基于已采集数据推理生成，财报解读有后端采集的财报数据支撑。分析问题中需明确引导 LLM 基于已有数据进行分析，避免幻觉编造。 |
| FR-03 | 双触发方式 | 自选列表选股 + 手动输入股票代码 |
| FR-04 | 分析结果持久化 | SaveAIResponseResult 保存，GetAIResponseResult 加载历史 |
| FR-05 | UI 风格统一 | 保持深色主题、glassmorphism 卡片风格 |
| FR-06 | Prompt 使用策略 | 使用 Settings 全局 Prompt，sysPromptId 传 null |

## 3. 架构与模块

### 3.1 整体架构

```
用户操作（选股/输入代码）
    ↓
AIAnalysis.tsx（前端组件）
    ↓ 调用 Wails IPC
NewChatStream(stock, stockCode, question, aiConfigId, null, true, false)
    ↓
app.go NewChatStream()
    ↓
openai_api.go NewChatStream()
    ↓ 并发采集 8 种数据
    ↓ 构建对话上下文
    ↓ 调用 LLM 流式生成
    ↓
Wails EventsEmit("newChatStream", msg)
    ↓
前端 EventsOn 接收流式数据
    ↓
解析 Markdown 内容展示 + 保存结果
```

### 3.2 模块职责

| 模块 | 文件 | 职责 |
|------|------|------|
| 前端分析页面 | `frontend/src/app/components/AIAnalysis.tsx` | UI 展示、用户交互、流式数据接收与渲染 |
| Wails IPC 绑定 | `frontend/wailsjs/go/main/App.js` | 前端调用后端方法的桥接层（已有，无需修改）|
| 后端分析入口 | `app.go` | NewChatStream 方法（已有，无需修改）|
| 数据采集与 LLM | `backend/data/openai_api.go` | 并发采集数据、构建 prompt、调用 LLM（已有，无需修改）|

### 3.3 关键决策

**选择 NewChatStream 而非 ChatWithAgent 的原因：**
- NewChatStream 已经内置了完整的并发数据采集流程（8种数据源：K线、财报、互动问答、宏观经济、资讯等）
- 数据采集逻辑成熟稳定，不需要重新实现
- ChatWithAgent（ReAct Agent）更适合自由对话场景，分析场景用 NewChatStream 更可控
- 前端只需改造 AIAnalysis.tsx 一个文件，后端无需修改

EventsOn("newChatStream", (msg: any) => {

    // 流式回复完成
  } else if (typeof msg === "object") {
    // msg.content: LLM 流式回复片段
    // msg.chatId: 对话 ID（用于保存）

### 4.3 流式数据格式

后端返回的每条消息格式：
```json
{
  "code": 0,
  "question": "分析贵州茅台...",
  "extraContent": "",
  "chatId": "uuid-xxx",
  "content": "## 技术分析\n\nMACD指标显示..."
}
```

LLM 返回的 content 是 Markdown 格式的分析文本，前端需要：
1. 实时拼接 content 片段
2. 渲染 Markdown 内容
3. 流式完成后保存完整结果

### 6.2 分析触发逻辑

```typescript
const startAnalysis = async (stockName: string, stockCode: string) => {
  setIsAnalyzing(true);
  setAnalysisContent('');
  setAnalysisMode('new');
  
  // 先检查是否有历史结果
  try {
    // GetAIResponseResult 参数是 stock 字符串（按股票代码查询最新结果）
    const history = await GetAIResponseResult(stockCode);
    if (history && history.content) {
      setHistoryResult(history);
      // 仍然开始新分析，但展示历史结果供参考
    }
  } catch (e) {}
  
  // 监听流式消息
  const cleanup = EventsOn("newChatStream", (msg: any) => {
    if (msg === "DONE") {
      setIsAnalyzing(false);
      // 保存分析结果
      if (analysisContent && chatId) {
        SaveAIResponseResult(stockCode, stockName, analysisContent, chatId, question, selectedAiConfig);
      }
    } else if (typeof msg === "object") {
      if (msg.chatId) setChatId(msg.chatId);
      if (msg.content) setAnalysisContent(prev => prev + msg.content);
      if (msg.extraContent) setAnalysisContent(prev => prev + msg.extraContent);
    }
  });
  
  // 触发后端分析
  const question = `请对 ${stockName}(${stockCode}) 进行全面深度分析，包括：
1. 技术面分析（MACD、RSI、均线、KDJ等指标解读）
2. 基本面分析（市盈率、市净率、ROE等财务指标）
3. 资金流向分析（主力资金、散户资金动向）
4. 市场情绪分析（近期新闻舆论导向）
5. 行业对比分析（在所属行业中的竞争地位）
6. 财报深度解读（最新财报关键数据及同比变化）
7. 研报摘要（近期券商研究报告要点）
8. 风险评估与目标价位
9. 综合投资建议`;
  
  await NewChatStream(stockName, stockCode, question, selectedAiConfig, null, true, false);
  
  return cleanup; // 返回清理函数
};
```

### 6.4 Markdown 渲染方案

分析结果是 LLM 返回的 Markdown 文本，前端需要渲染为富文本。方案：

选项 A：使用简单的 Markdown-to-HTML 转换（推荐，轻量）
- 自己实现一个简单的 Markdown 渲染函数
- 支持标题、加粗、列表、表格、代码块等基本语法
- 保持与现有深色主题的视觉一致性

选项 B：引入 react-markdown 库
- 功能完整，支持所有 Markdown 语法
- 需要新增依赖

推荐选项 A，使用自建的轻量 Markdown 渲染，避免引入额外依赖。也可以直接用 dangerouslySetInnerHTML 配合简单正则替换。

### 6.5 关键交互细节

1. **分析中状态**：显示脉冲动画 + "AI 正在分析中..." 文本，分析内容实时流式追加
2. **分析完成**：内容停止追加，显示"分析完成"提示，自动保存结果
3. **历史结果**：进入页面时先检查该股票是否有历史分析，有则显示上次结果和更新时间
4. **重新分析**：按钮触发新一轮分析，清空旧内容
5. **AI 模型选择**：下拉选择已配置的 AI 模型（来自 GetAiConfigs）
6. **错误处理**：网络异常、AI 配置缺失等情况显示友好提示
7. **边界场景处理**：
   - 无自选股：显示提示"暂无自选股，请先在自选列表中添加股票"，并提供跳转按钮
   - AI 未配置：分析前验证 aiConfigs.length > 0，若为空显示"请先在系统设置中配置 AI 模型"
   - 网络超时：60 秒超时后显示"分析超时，请检查网络连接或 AI 服务配置"
   - 流式消息异常：msg.content 为空时跳过，避免追加空内容

### 6.6 事件监听器生命周期管理

防止事件监听器堆积和内存泄漏，必须严格遵守以下规范：

1. **分析前清理**：每次触发新分析前，先调用 EventsOff("newChatStream") 清理旧监听器
2. **组件卸载清理**：useEffect 返回的 cleanup 函数中调用 EventsOff("newChatStream")
3. **同时只允许一个分析**：使用 isAnalyzing 状态锁，分析进行中禁止触发新分析
4. **超时保护**：设置 60 秒超时定时器，超时后自动 EventsOff 并重置状态

参考实现：
- Watchlist.tsx 中已有 EventsOn/EventsOff 的包装方式（使用可选链 ?. 确保 Wails 运行时存在）
- 应采用相同的包装方式

### 6.7 中止分析功能

由于后端 NewChatStream 没有现成的中止方法（不同于 AbortSummaryStockNews），本次采用前端侧中止方案：

1. **前端中止实现**：
   - 分析进行中显示"停止分析"按钮
   - 点击后调用 EventsOff("newChatStream") 停止接收消息
   - 重置 isAnalyzing 状态
   - 已接收的部分内容仍然展示（标记为"分析已中止，以下为部分结果"）

2. **防重复触发**：
   - 中止后允许立即开始新的分析
   - 新分析开始前自动清理旧监听器

注意：前端中止只是停止接收消息，后端 LLM 调用仍会继续执行直到完成。这是可接受的，因为后端调用有超时保护（默认 300 秒），不会无限占用资源。

### 6.8 打字机效果与分块卡片显示

为提升分析过程的视觉体验，实现以下优化：

1. **打字机效果**：LLM 流式回复部分启用逐字显示效果
   - 使用 requestAnimationFrame 或 setInterval（10ms）逐字追加显示
   - 仅在 LLM 回复阶段启用，数据采集阶段正常显示
   - 用户可通过点击"跳过动画"立即显示全部已接收内容

2. **分块卡片显示**：识别 Markdown 二级标题（##），将分析报告按维度拆分为独立卡片
   - 每个 ## 标题作为一个卡片的标题
   - 卡片逐个 slide-in 动画出现
   - 支持单个卡片的展开/折叠
   - 保持现有 glassmorphism 卡片风格

### 6.9 分析历史对比（v1.1 规划）

支持查看同一股票的历史分析结果对比：

1. **历史记录列表**：展示该股票所有历史分析记录（时间、使用的 AI 模型）
2. **结论变化提示**：对比前后两次分析的关键结论变化（如"上次：买入 → 本次：持有"）
3. **时间轴视图**：以时间轴形式展示分析历史

注意：此功能依赖 SaveAIResponseResult 是否按 stockCode 追加保存多条记录。如当前实现为覆盖式保存，需后续调整后端逻辑支持多条历史记录。本次实现先预留 UI 入口，具体功能可在 v1.1 版本完善。

### 6.10 细粒度进度提示

分析过程中展示更详细的进度信息：

1. **阶段提示**：根据时间和消息内容推断当前阶段
   - "正在采集市场数据..."（0-10秒）
   - "正在分析技术指标..."（10-20秒）
   - "AI 正在生成分析报告..."（20秒后开始收到 LLM 回复时）
   - "分析完成"（收到 DONE 时）

2. **进度条**：使用时间估算的模糊进度条（非精确进度）
   - 数据采集阶段：0-40%（基于时间估算，约 10-15 秒）
   - LLM 生成阶段：40-95%（基于已接收内容长度）
   - 完成：100%

3. **实现方式**：
   - 使用 extraContent 中的提示信息辅助判断阶段
   - 结合 setTimeout 和 content 接收事件更新进度

## 8. 风险与注意事项

1. **NewChatStream 是 void 方法**：它不返回数据，而是通过 Wails Events 推送。前端必须在调用前先注册 EventsOn 监听器。
2. **事件名必须用 "newChatStream"**：这是 app.go 中硬编码的事件名。
3. **并发分析冲突**：如果用户快速切换股票触发多次分析，需要在前端做防抖，确保同一时间只有一个分析在进行。
4. **AI 配置依赖**：分析前需要确认至少有一个 AI 配置，否则需提示用户先去 Settings 配置。
5. **GetStockList 参数**：传空字符串获取默认分组的自选股列表。
6. **Markdown 渲染安全**：使用 dangerouslySetInnerHTML 时注意 XSS 风险，LLM 返回内容来源可控，风险较低。
7. **不修改后端**：本方案完全复用现有后端能力，零后端改动。
8. **事件监听器泄漏**：必须在组件卸载和新分析开始前清理旧的 EventsOn 监听器，否则会导致多个监听器同时响应同一事件。
9. **FR-02 扩展维度的数据可靠性**：行业对比和研报摘要维度缺乏专门的数据采集，完全依赖 LLM 推理。应在 prompt 中明确要求 LLM 只基于提供的数据分析，不要编造数据。后续可考虑在后端补充行业对比数据的采集逻辑。
10. **中止分析的后端行为**：前端中止只停止接收消息，后端 LLM 调用会继续执行。可接受，因后端有 300 秒超时保护。
11. **打字机效果性能**：逐字显示会频繁触发 React 重渲染，建议使用 useRef 存储完整内容，仅定期 setState 更新显示内容，避免性能问题。
12. **分块卡片识别的健壮性**：LLM 输出的 Markdown 格式可能不完全规范（如标题层级混用），分块逻辑需容错处理。
