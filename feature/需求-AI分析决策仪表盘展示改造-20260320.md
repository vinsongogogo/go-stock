# 需求：AI 分析决策仪表盘展示改造

## 需求背景

当前 go-stock 项目的 AI 股票分析结果以纯文本/Markdown 格式展示，视觉效果差、关键信息不突出。参考 daily_stock_analysis 项目的「决策仪表盘」展示方案，将分析结果改造为结构化的仪表盘样式，提升信息可读性和用户体验。

## 参考项目

daily_stock_analysis (https://github.com/ZhuLinsen/daily_stock_analysis)
- 本地路径：/Users/daxue_1/ai-workspace/daily_stock_analysis
- 核心参考文件：
  - Prompt 设计：src/analyzer.py（SYSTEM_PROMPT，行 502-686）
  - 数据模型：src/schemas/report_schema.py
  - 前端仪表盘：apps/dsa-web/src/components/report/
  - 情绪仪表：apps/dsa-web/src/components/common/ScoreGauge.tsx

#### 1.2 Prompt 改造要求

- 参考 daily_stock_analysis 的 SYSTEM_PROMPT 风格（src/analyzer.py 行 502-686）
- 包含核心交易理念（严禁追高、趋势交易、筹码分析等评判标准）
- 包含评分标准（80-100 强烈买入、60-79 买入、40-59 观望、0-39 卖出）
- 在 Prompt 中明确要求 AI 输出 JSON 格式
- 将收集到的行情数据以 Markdown 表格形式传入（现有逻辑已有这部分，保持不变）

#### 1.3 改造位置

- 系统 Prompt：需要新增一个专门用于「决策仪表盘」的系统 Prompt
- 现有 Prompt 模板管理（prompt_template_api.go）：新增仪表盘 Prompt 模板
- openai_api.go 中 NewChatStream：流式输出逻辑不变，AI 输出的内容格式改为 JSON

### 二、前端结构化展示改造

将 AIAnalysis.tsx 中的分析结果展示从当前的卡片/Markdown 方式改造为完整的决策仪表盘。

#### 2.1 展示模块

参考截图和 daily_stock_analysis 前端实现，需实现以下展示模块：

**模块 A：股票头部信息**
- 股票名称（大号字体）
- 股票代码 + 分析日期
- 当前价格 + 涨跌幅（涨绿跌红或涨红跌绿，跟随用户习惯）

**模块 B：Market Sentiment 情绪仪表盘**
- SVG 环形进度条，参考 ScoreGauge.tsx 的实现
- 中心显示分数（0-100）
- 下方显示情绪标签（极度悲观/悲观/中性/乐观/极度乐观）
- 颜色映射：恐惧红色、中性紫色、贪婪青色
- 带发光效果（feGaussianBlur）

**模块 C：KEY INSIGHTS 关键洞察**
- 显示 analysis_summary 综合分析摘要
- 或 dashboard.core_conclusion.one_sentence 核心结论

**模块 D：操作建议 + 趋势预测卡片**
- 两列布局
- 操作建议卡片：显示 operation_advice（买入/观望/卖出等）
- 趋势预测卡片：显示 trend_prediction（看多/震荡/看空等）
- 带图标和颜色区分

**模块 E：STRATEGY POINTS 狙击点位**
- 四列网格布局
- 理想买入价、二次买入价、止损价位、止盈目标
- 每个价格带颜色标识（买入绿色、止损红色、止盈金色）
- 底部渐变装饰线

**模块 F：操作检查清单**
- 列表展示 action_checklist
- 每项以 ✅/⚠️/❌ 开头标记状态
- 视觉化展示（绿色/黄色/红色背景）

**模块 G：NEWS FEED 相关资讯**
- 展示 intelligence.latest_news 和相关新闻
- 列表形式，每条新闻显示标题和摘要
- 可选：跳转链接

#### 2.2 布局设计

参考截图的两栏布局：
- 左侧（约 2/3 宽度）：股票头部 → 关键洞察 → 操作建议/趋势卡片
- 右侧（约 1/3 宽度）：情绪仪表盘
- 下方全宽：狙击点位 → 检查清单 → 相关资讯

#### 2.3 样式要求

- 暗色主题（与现有项目风格保持一致）
- 使用 Tailwind CSS（项目已有）
- 卡片边框带微发光效果
- 价格和数字使用等宽字体（font-mono）
- 整体风格参考截图的科技感设计

### 三、新旧数据兼容

#### 3.1 自动检测逻辑

前端需要自动检测分析结果的数据格式：
- 如果 Content 包含有效的结构化 JSON（能解析出 sentiment_score + dashboard 字段）→ 用仪表盘模式展示
- 如果是纯文本/Markdown → 用现有的 Markdown 渲染模式展示（保持不变）

#### 3.2 降级策略

- JSON 解析失败时自动降级为 Markdown 展示
- 部分字段缺失时，缺失的模块不渲染，其他模块正常展示
- 保留「展开详情」按钮，可查看完整的原始文本

### 四、数据流不变

- 后端流式输出机制不变（EventsEmit + SSE 事件流）
- 前端流式接收逻辑不变
- 分析结果存储方式不变（AIResponseResult.Content 存完整文本）
- 前端在流式接收完成后，尝试从 Content 中解析 JSON 结构化数据
- 保存和加载逻辑不变

## 不在范围内

- 不改变后端数据采集逻辑（行情数据、新闻数据的获取方式不变）
- 不新增社交舆情数据源（如 Reddit、X 等）
- 不改变数据库表结构
- 不改变流式传输机制
- 不做多语言支持（保持中文）
- 不做 AI 回测功能
- 不做分析结果对比功能

## 验收标准

1. 新分析的股票结果以仪表盘形式展示，包含全部 7 个模块
2. 历史纯文本记录继续以 Markdown 方式正常展示
3. 情绪仪表盘 SVG 动画正常，颜色随分数变化
4. 狙击点位显示具体价格数值
5. 操作检查清单以可视化方式展示
6. 整体视觉风格与现有暗色主题协调
7. 前端构建无报错
