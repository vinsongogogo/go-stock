# 需求：AI股票分析卡死修复

## 1. 背景

当前 go-stock 应用中，用户点击"AI股票分析"菜单后，整个应用会卡死数秒甚至更长时间，无法进行任何操作。经过两轮深入调查，确认根因是前端初始化时错误地加载了全量股票数据（5000+条），导致 React 渲染卡死。

## 2. 用户原始需求

用户反馈：打开 AI 股票分析功能，整个应用会卡死，无法操作。期望打开后能快速响应、正常使用。

## 3. 问题根因分析

### 3.1 核心根因：GetStockList('') 返回全量股票数据（P0-致命，贡献度 90%）

**问题链路：**

1. `AIAnalysis.tsx` 第 355 行初始化时调用 `GetStockList('')`，传入空字符串
2. 后端 `stock_data_api.go` 第 599-612 行，`GetStockList` 方法将空字符串拼接为 SQL：
   ```sql
   WHERE name LIKE '%%' OR ts_code LIKE '%%'
   ```
   这实际上匹配了整个 StockBasic 表的所有记录（5000+ 条）
3. 5000+ 条股票数据返回前端后，`setStockAnalysisList(initialStates)` 设置了 5000+ 条记录
4. `AIAnalysis.tsx` 第 1022-1026 行 `stockAnalysisList.map(stock => renderStockCard(stock))` 一次性渲染 5000+ 个卡片组件
5. 每个卡片由 `renderStockCard()`（第 775-901 行）渲染，包含状态 UI、结构化数据卡片（4 维评分）、Markdown 渲染、动画过渡等复杂 DOM
6. React Virtual DOM 的 reconciliation 需要遍历 5000+ 个节点树，主线程被长期阻塞，页面完全无响应

**根本原因：AI 分析页面应该只加载用户的自选股（通常 10-50 只），而不是全市场股票。**

### 3.2 次要原因：并发 GetAIResponseResult 请求（P2-低，贡献度 10%）

- `AIAnalysis.tsx` 第 381-399 行，初始化时对每只股票发起 `GetAIResponseResult` 并发请求
- 当数据量为 5000+ 时，产生 5000+ 个并发数据库查询
- 每个请求返回都触发一次 `setStockAnalysisList` 状态更新，叠加渲染压力
- **注意**：如果核心根因修复后（只加载自选股，通常 10-50 只），此问题自然减轻，但仍建议加分批控制

### 3.3 已排除的假设

| 假设 | 验证结论 | 原因 |
|------|----------|------|
| NewChatStream 8个goroutine无超时 | **排除** | NewChatStream 仅在用户点击"开始分析"时调用，不在页面初始化时调用，与"打开就卡死"无关 |
| Keep-Alive 与初始化逻辑交互 | **排除** | Keep-Alive 首次打开只挂载一次，cleanup 函数正确清理事件监听和定时器，不会重复初始化或 Promise 悬挂 |

## 4. 澄清后需求明细

### 4.1 核心修复：初始化数据源修正
- AIAnalysis 初始化时应只加载用户的**自选股列表**，不加载全市场股票
- 方案选择：
  - 方案A：前端调用一个专门获取自选股的后端方法（如已有的 GetFollowedStocks 或新增）
  - 方案B：修改 GetStockList 后端逻辑，空字符串时只返回自选股
  - 方案C：前端传递特殊参数标识"只要自选股"
- 需确认后端是否有现成的"获取自选股列表"API

### 4.2 渲染性能优化（防御性措施）
- 即使数据量降到 10-50 只，仍建议：
  - 并发 GetAIResponseResult 请求加分批控制（每批 5 个）
  - 合并频繁的 React 状态更新，减少重渲染次数
  - 如果未来自选股数量增长，考虑虚拟化列表（react-window）

### 4.3 前端健壮性增强
- 初始化加载添加异常处理和超时保护
- 组件隐藏时取消未完成的请求（AbortController）

## 5. 影响范围

| 模块 | 文件 | 改动类型 | 优先级 |
|------|------|----------|--------|
| 前端-AI分析 | AIAnalysis.tsx | 修改初始化数据源、分批加载 | P0 |
| 后端-股票数据（可选） | stock_data_api.go 或 app.go | 提供自选股专用 API 或修改现有 API | P0 |
| 前端-AI分析 | AIAnalysis.tsx | 渲染性能优化 | P2 |

## 6. 非功能需求
- 页面首次打开到可交互时间 ≤ 2 秒
- 自选股 50 只时历史结果全部加载 ≤ 5 秒
- 页面切换无明显卡顿

## 7. 验收标准
1. 打开 AI 股票分析页面，页面在 2 秒内可交互，无冻屏
2. 初始化只加载自选股（而非全市场股票），数据量可控
3. 自选股数量 ≥ 50 时，历史结果分批加载，不阻塞 UI
4. 从其他页面切换到 AI 分析再切回，应用响应流畅
