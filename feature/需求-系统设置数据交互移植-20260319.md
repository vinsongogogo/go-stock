# 需求-系统设置数据交互移植

## 1. 需求背景

当前 frontend（React/TSX）下的系统设置页面 Settings.tsx 只有 UI 框架，没有任何后端数据交互。所有设置都存在本地 state 中，页面刷新或应用重启后丢失。需要参考 frontend_vue 的 settings.vue 实现，将完整的数据交互逻辑移植过来。

## 2. 需求范围

### 2.1 核心数据交互（必须）

1. 页面初始化加载：组件挂载时调用 GetConfig() API，将后端配置映射到 React state
2. 保存设置：handleSave 调用 UpdateConfig(config) API 持久化到后端数据库
3. 导出配置：调用 ExportConfig() 后端 API（通过系统文件保存对话框）
4. 导入配置：从本地文件读取 JSON 后调用 UpdateConfig() 同步到后端

### 2.2 设置字段补全（必须）

React 版本需要与 Vue 版本的 SettingConfig 数据模型完全对齐，补充以下缺失字段：

基础设置：
- tushareToken（已有，需绑定后端字段）
- updateBasicInfoOnStart 启动时更新基础信息（布尔开关）
- refreshInterval 数据刷新间隔（数字输入，单位秒）
- darkTheme 暗黑主题（布尔开关）
- browserPath 浏览器安装路径（已有，需绑定后端字段）
- enableFund 指数基金（布尔开关）
- enableAgent AI智能体（布尔开关）
- qgqpBId 东财唯一标识（文本输入）
- sponsorCode 赞助码（文本输入 + 验证按钮）

通知设置：
- dingPushEnable 钉钉推送（布尔开关）
- dingRobot 钉钉机器人接口地址（条件文本输入，仅当 dingPushEnable 为 true 时显示）
- localPushEnable 本地推送（布尔开关）
- enableDanmu 弹幕功能（布尔开关）
- enableNews 显示滚动快讯（布尔开关）
- enablePushNews 市场资讯提醒（布尔开关）
- enableOnlyPushRedNews 只提醒红字或关注个股的新闻（条件开关，仅当 enablePushNews 为 true 时显示）
- 发送测试通知按钮

AI 设置：
- openAiEnable AI诊股总开关（布尔开关，控制整个 AI 区域显示隐藏）
- crawlTimeOut 爬虫超时秒数（数字输入，最小值30）
- kDays 日K线数据天数（数字输入，范围30-60）
- httpProxyEnabled 爬虫http代理启用（布尔开关）
- httpProxy http代理地址（条件文本输入，仅当 httpProxyEnabled 为 true 时显示）
- prompt 默认系统提示词（多行文本域）
- questionTemplate 默认个股分析提示词（多行文本域）

### 2.3 AI 模型配置动态管理（必须）

参考 Vue 版本，实现 aiConfigs 数组的动态管理：
- 渲染多个 AI 配置卡片列表
- 每个配置包含：name, baseUrl, apiKey（密码输入可切换显示）, modelName, temperature, maxTokens, timeOut, httpProxy, httpProxyEnabled
- 支持添加新配置（默认值：baseUrl=https://api.deepseek.com, modelName=deepseek-reasoner, temperature=0.1, maxTokens=8192, timeOut=6000）
- 支持删除单个配置
- 支持编辑每个配置的所有字段

### 2.4 条件显示逻辑（必须）

- AI 设置区域：仅当 openAiEnable 为 true 时显示 AI 相关的所有配置
- 钉钉机器人地址：仅当 dingPushEnable 为 true 时显示
- 只提醒红字新闻：仅当 enablePushNews 为 true 时显示
- http 代理地址（全局）：仅当 httpProxyEnabled 为 true 时显示
- 每个 AI 配置的代理地址：仅当该配置的 httpProxyEnabled 为 true 时显示

### 2.5 赞助码验证（必须）

- 调用 CheckSponsorCode(code) API 验证
- 在保存配置前进行验证

### 2.6 删除 React 中不需要的字段

以下是 React 当前有但 Vue 版本/后端模型中不存在的字段，应该移除：
- validateClipboard、fillTheme、aiLibrary、subscribeNotify、alertFunction、crawlerNotify 等伪字段

## 3. 技术约束

- 仅修改 frontend/src/app/components/Settings.tsx 文件
- 使用已有的 wailsjs 绑定：GetConfig, UpdateConfig, ExportConfig, CheckSponsorCode
- wailsjs 绑定文件路径：frontend/wailsjs/go/main/App.js 和 App.d.ts
- 数据模型定义：frontend/wailsjs/go/models.ts
- 保持现有 Tailwind CSS 风格和视觉设计
- 使用 React hooks（useState, useEffect）管理状态

## 4. 参考文件

- Vue 源码：frontend_vue/src/components/settings.vue
- React 当前：frontend/src/app/components/Settings.tsx
- 后端模型：backend/models/models.go
- 设置 API：backend/data/settings_api.go
- Wails 绑定类型：frontend/wailsjs/go/main/App.d.ts
- 数据模型类型：frontend/wailsjs/go/models.ts

## 5. 验收标准

1. 打开系统设置页面时，自动从后端加载已保存的配置并显示
2. 修改任意设置后点击保存，数据持久化到后端数据库，重启应用后设置仍在
3. AI 模型配置支持增删改，保存后不丢失
4. 条件显示逻辑正确（开关控制区域显隐）
5. 导出配置通过后端 API 调用系统文件保存对话框
6. 导入配置后数据同步到后端
7. 所有设置字段与后端 SettingConfig 模型完全对齐

## 6. 待产品确认

无（需求明确，参考 Vue 版本 1:1 移植逻辑）

## 7. 澄清后需求明细

本需求为纯技术移植，将 frontend_vue/src/components/settings.vue 中的数据交互逻辑（API 调用、状态管理、条件显示、AI 配置管理）完整移植到 frontend/src/app/components/Settings.tsx，保持 React 版本现有的 UI 风格不变。
