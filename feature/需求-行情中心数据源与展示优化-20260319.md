# 需求：行情中心数据源与展示优化

> 日期：2026-03-19
> 状态：需求已确认

---

## 一、背景与现状分析

行情中心（Dashboard）包含三个核心模块：**市场情绪强弱**、**行业热力图**、**24小时日次**。当前实现存在以下问题：

### 1.1 市场情绪强弱（MarketGauge）

**当前实现**：
- 前端组件：`frontend/src/app/components/MarketGauge.tsx`
- 数据来源：调用 `AnalyzeSentimentWithFreqWeight('')`，对最近24小时新闻文本做 NLP 情感分析
- 展示方式：SVG 圆形仪表盘 + 看涨/中性/看跌百分比 + 热词排行

**主要问题**：
- 情绪计算完全依赖新闻文本的 NLP 分析，缺少**真实市场数据**支撑（涨跌停统计、换手率、北向资金等）
- 情绪指标单一，无法反映多维度的市场活跃度
- 没有历史趋势对比，用户无法感知情绪变化方向

### 1.2 行业热力图（TreeMap）

**当前实现**：
- 前端组件：`frontend/src/app/components/TreeMap.tsx`
- 数据来源：**完全使用静态硬编码数据**（6个行业板块 + 12个概念标签 + 8个热词）
- 后端已有 `GetIndustryRank`（新浪行业排行）和 `GetIndustryMoneyRankSina`（行业资金流）接口但**未接入前端**

**主要问题**：
- 前端展示的行业数据全部是写死的假数据，无任何实时性
- 行业板块仅6个，无法反映真实的31个申万一级行业
- 概念标签（芯片、5G、AI等）也是静态的，不能反映当日真实热点
- 缺少行业资金流向、涨跌排名等关键指标

### 1.3 24小时日次

**当前实现**：
- 位于 TreeMap 右侧的"24H热词"区域，使用**静态数据**
- 实时资讯流（NewsFeed）组件已完善，支持财联社/新浪/外媒三源
- 但"24小时日次"概念（日内重要事件时间轴）尚未实现

**主要问题**：
- 24H 热词是硬编码的假数据，未调用后端的 `NewsAnalyze` 词频分析能力
- 缺少真正的"日次"概念——即每日重要市场事件的时间轴展示
- 未整合涨跌停事件、行业异动、资金异动等结构化事件

## 四、需求描述

### 需求 1：市场情绪强弱 — 多维度数据源升级

**目标**：将市场情绪从纯文本 NLP 升级为「结构化市场数据 + NLP」综合评估模型。

#### 4.1 数据维度扩展

在现有 NLP 情感分析基础上，新增以下结构化指标：

| 指标 | 数据源 | 更新频率 | 权重建议 |
|------|--------|----------|---------|
| 涨跌停统计 | `limit_list_d` 或现有爬虫 | 盘后 | 高 |
| 涨跌家数/涨跌比 | `daily_basic` 或现有爬虫 | 盘后 | 高 |
| 市场平均换手率 | `daily_basic` | 盘后 | 中 |
| 北向资金净流入 | `moneyflow_hsgt` 或现有爬虫 | 盘后 | 高 |
| 融资融券余额变化 | `margin` | 盘后 | 中 |
| 新闻情感分析 | 现有 NLP | 实时 | 中 |

#### 4.2 情绪综合评分模型

- 设计一个加权综合评分模型，将多个维度标准化后加权求和
- 评分范围保持 -100 到 100
- 支持配置各维度权重（可在设置中调整或使用默认值）

#### 4.3 前端展示优化

- 保持现有仪表盘样式
- 新增各维度的子指标展示（迷你指标卡片）
- 展示涨停家数/跌停家数、北向资金净流入额等关键数字
- 可选：新增情绪历史趋势小图（近7日/30日）

---

### 需求 2：行业热力图 — 接入实时数据

**目标**：将行业热力图从静态硬编码改为实时数据驱动。

#### 4.4 数据源方案（二选一，待确认）

**方案 A：使用现有爬虫接口（推荐，零积分成本）**
- 调用已有的 `GetIndustryRank`（新浪行业排行）获取行业涨跌数据
- 调用已有的 `GetIndustryMoneyRankSina` 获取行业资金流向
- 优点：无需 tushare 积分，接口已实现
- 缺点：数据维度较少，无 PE/PB 等估值数据

**方案 B：使用 Tushare 接口（更专业，需积分）**
- `index_classify` 建立行业字典
- `sw_daily` 获取申万31个一级行业日线数据（涨跌幅、成交量、PE/PB）
- `moneyflow_ind_dc` 获取行业资金流向
- 优点：数据更全面、更专业
- 缺点：需要5000-6000积分

#### 4.5 前端展示需求

- 热力图展示所有行业板块，面积按市值或成交量映射
- 颜色按涨跌幅映射（绿→红渐变）
- 点击行业可展开查看：涨跌幅、成交额、资金净流入、领涨股等
- 概念标签改为动态：基于当日涨幅最大的概念/题材自动生成
- 支持切换：申万行业 / 概念板块（如使用 tushare 方案）

---

### 需求 3：24小时日次 — 动态热词与市场事件时间轴

**目标**：将静态24H热词升级为动态内容，新增日内市场事件时间轴。

#### 4.6 24小时热词（动态化）

- 调用后端已有的 `NewsAnalyze` / `countWordFrequencyWithWeight` 对最近24小时资讯做词频分析
- 热词按权重排序，展示 Top 8-10
- 每30分钟或1小时自动刷新
- 热词旁显示热度变化趋势（上升/下降箭头）

#### 4.7 日内市场事件时间轴（新增）

整合以下事件源，按时间轴展示当日重要市场事件：

| 事件类型 | 数据来源 | 示例 |
|---------|---------|------|
| 涨停/跌停突破 | `limit_list_d` 或爬虫 | "10:15 某某股涨停，连板3天" |
| 行业异动 | 行业数据 | "14:30 半导体板块大涨3.2%" |
| 北向资金异动 | `moneyflow_hsgt` 或爬虫 | "11:00 北向资金净流入超50亿" |
| 重要快讯 | 现有资讯流（isRed标记） | "09:30 央行宣布降准" |

- 时间轴按时间倒序展示
- 支持按事件类型筛选
- 事件卡片包含时间、类型标签、简述

## 五、产品确认结果

1. **行业热力图数据源选择** → **方案A：使用现有爬虫接口**（`GetIndustryRank` + `GetIndustryMoneyRankSina`），零积分成本
2. **Tushare 积分现状** → 积分等级不够，暂不使用高积分接口（`sw_daily`/`moneyflow_ind_dc`/`ths_index` 等暂不接入）
3. **市场情绪模型** → 使用**固定默认权重**，无需用户可配置
4. **日内事件时间轴** → **需要实现**
5. **数据更新频率** → 暂不考虑盘中实时数据，**接受盘后更新**
6. **24小时快讯数据源** → **接入 tushare `news` 接口**作为补充源（需单独申请权限，与积分等级无关）

## 六、澄清后需求明细

### 6.1 市场情绪强弱 — 多维度综合评分

**数据源**：以现有爬虫 + 低积分 tushare 接口为主
- 涨跌停统计：优先使用现有爬虫，备选 `stk_limit`（2000积分）
- 涨跌家数/涨跌比：通过现有爬虫或 `daily_basic`（2000积分）获取
- 北向资金净流入：优先使用现有爬虫，备选 `moneyflow_hsgt`（2000积分）
- 新闻情感分析：保留现有 NLP 分析

**评分模型**：固定默认权重，加权求和，范围 -100 到 100
- 涨跌停比：权重 30%（涨停多=正向，跌停多=负向）
- 涨跌家数比：权重 25%
- 北向资金净流入：权重 20%（正=看涨，负=看跌）
- 新闻 NLP 情感：权重 25%

**前端展示**：
- 保持现有仪表盘圆形样式
- 仪表盘下方新增迷你指标卡片：涨停家数、跌停家数、北向资金净流入额、涨跌家数比
- 热词排行保留

### 6.2 行业热力图 — 使用方案A

**数据源**：
- 调用已有的 `GetIndustryRank`（新浪行业排行）获取各行业涨跌幅
- 调用已有的 `GetIndustryMoneyRankSina` 获取行业资金流向
- 后端需新增统一接口整合这两组数据返回给前端

**前端展示**：
- 热力图区域：按行业涨跌幅着色的矩形卡片网格（替换静态假数据）
- 每个行业卡片展示：行业名、涨跌幅、资金净流入方向（箭头）
- 颜色映射：跌（绿）→ 涨（红）
- 概念标签区域：改为动态展示当日涨幅最大的行业板块名称（取涨幅 Top 8）
- 点击行业卡片暂不做详情展开（后续可扩展）

### 6.3 24小时日次 — 动态热词 + 事件时间轴

**24小时动态热词**：
- 调用后端 `NewsAnalyze` / `countWordFrequencyWithWeight` 对最近24小时资讯做词频分析
- 展示 Top 8 热词，按权重排序
- 每60分钟自动刷新
- 热词旁显示热度趋势（上升/下降/持平箭头）

**日内市场事件时间轴**：
- 整合以下事件源，按时间倒序展示当日重要事件：
  - 重要快讯：现有资讯流中 `isRed` 标记的重要新闻
  - 涨停/跌停突破：从涨跌停数据中提取
  - 行业异动：从行业排行数据中提取涨跌幅异常的行业
  - 北向资金异动：从北向资金数据中提取大额变动
- 事件卡片包含：时间、事件类型标签（快讯/涨停/行业/资金）、简述
- 数据更新频率：盘后更新结构化事件，快讯类实时更新

**Tushare `news` 接口接入**：
- 作为现有三个爬虫源（财联社/新浪/外媒）的第四个补充源
- 对接 tushare `news` 接口，支持的数据源：新浪财经、华尔街见闻、同花顺、东方财富、财联社等
- 存储到现有 Telegraph 表，Source 字段标记为 "tushare"
- 前端新增一个频道 tab 或合并到现有频道中

## 八、非功能需求

- 数据接口调用需做**缓存**，避免频繁请求 tushare 或爬虫源
- 盘后数据建议通过**定时任务**（已有 `cron_task_api.go`）每日自动拉取
- 前端需做**加载状态**和**错误处理**，数据未就绪时展示占位符而非空白
