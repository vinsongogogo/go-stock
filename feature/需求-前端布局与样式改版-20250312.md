# 需求文档：前端页面布局与样式整体改版

## 1. 需求概述

- **目标**：整体调整前端页面布局与样式，使他人难以看出与当前版本的关联性；通过「改变布局结构」与「改变 CSS 结构」两处可改动点达成。
- **背景/价值**：产品希望从视觉与结构上做明显区分，降低与现有版本的可辨识关联。

## 2. 业务通识摘要

- **当前无 `通识.md`**，建议在项目根或 `docs/` 下补充业务名词与规则。
- 与本需求相关的现有约定：
  - 应用为 Wails 桌面端，前端技术栈：Vue 3 + Vite，Naive UI + TDesign Vue Next，Vue Router（Hash）。
  - 主窗口标题为「大聪明」；主导航为左侧边栏 + 右侧内容区，路由包含：股票自选、市场行情、基金自选、Ai 智能体、研究中心、设置、关于、定时任务等。

## 3. 现状与代码结论

### 3.1 涉及模块/路径

| 类型       | 路径/说明 |
|------------|-----------|
| 根布局     | `frontend/src/App.vue` |
| 全局样式   | `frontend/src/style.css`，`frontend/index.html` 引用 |
| 路由       | `frontend/src/router/router.js` |
| 页面组件   | `frontend/src/components/` 下如 `stock.vue`、`market.vue`、`researchIndex.vue`、`settings.vue`、`about.vue`、`agent-chat.vue`、`cron-task-manager.vue`、`fund.vue` 等 |
| 全局组件   | `FloatingAiAssistant.vue`、各 Naive/TDesign 的 Provider 包裹在 `App.vue` |

### 3.2 当前布局结构（易被识别的特征）

- **整体**：`n-layout has-sider` → 左侧 `n-layout-sider`（固定宽度 220，折叠 64）+ 右侧 `n-layout-content`。
- **侧栏**：`n-menu` 垂直菜单，`mode="vertical"`，带图标与多级子项（股票自选下挂分组、市场行情下挂多子 tab 等）；类名 `app-sidebar`、`app-sidebar-menu`。
- **内容区**：顶部可选 `n-marquee` 跑马灯 → `n-scrollbar` → `RouterView`；加载时 `n-spin` + `n-skeleton`。
- **页面内**：各页不统一，常见为 `n-card` + `n-tabs`（如研究中心）、或 `n-grid` + `n-space`（如设置、市场部分子视图）；列表/表格多为 Naive 组件。

### 3.3 当前 CSS 结构（易被识别的特征）

- **全局**：`style.css` 中 `:root` 定义 `--app-bg`、`--sidebar-bg`、`--content-bg`、`--border-color` 等；`body` 字体为 Inter；`#app` 为 flex、100vh；大量 `.app-sidebar`、`.n-layout-sider.app-sidebar`、`.n-menu-item-content` 等选择器与色值（如 `#f1f5f9`、`#334155`、`#0f172a`）。
- **App.vue**：`<style scoped>` 内重复定义 `.app-sidebar`、`.app-sidebar-menu` 及 `--n-item-*` 等 Naive 菜单变量。
- **组件**：部分组件内联 style 或 `<style scoped>`；多处引用第三方 CSS（如 `tdesign-vue-next/es/style/index.css`、`md-editor-v3`、`@vavt/v3-extension`）。

### 3.4 与需求差异

- 需求要求「改变布局结构」与「改变 CSS 结构」以降低关联性，当前代码尚未做针对性改版，上述布局与类名/变量/色值均为可识别特征。

## 5. 澄清后需求明细

### 5.1 路由、菜单文案与入口顺序调整

- **描述**：
  - **路由**：path 与 name 全部更换为与现有一一对应的新命名，避免从 URL/name 直接联想旧版（建议见附录 A）。
  - **菜单文案**：所有侧栏与子菜单文案更换为同义或近义表述，功能不变（建议见附录 A）。
  - **入口顺序**：侧栏一级菜单顺序重排，与当前顺序明显不同（建议见附录 A）。
- **验收标准**：前端仅使用新 path/name；菜单展示为新文案与新顺序；历史书签/深链若有则需兼容或 301 到新 path。
- **涉及端/模块**：`frontend/src/router/router.js`、`frontend/src/App.vue`（menuOptions 顺序与 label）、所有 `router.push`/`RouterLink` 的 `to`（path/name/query 中与菜单相关的 name 需与文案一致）。

### 5.2 布局结构改版

- **描述**：主框架保持「左侧栏 + 右侧内容」，但调整侧栏宽度/折叠尺寸、内容区结构（如跑马灯/滚动区域排版）、以及**各子页面内部**布局（n-card、n-tabs、n-grid、n-space 等改为新排版与层级），使整体布局结构与当前版本明显不同。
- **验收标准**：主框架与子页面从 DOM 结构、类名、栅格/标签页用法上不易与旧版对应；侧栏仍为左侧、交互保留（折叠、拖拽、跑马灯、loading）。
- **涉及端/模块**：`App.vue`、`frontend/src/components/` 下所有页面级与列表/表单类组件。

### 5.3 整套主题与 CSS 改版

- **描述**：更换整套主题（含 Naive UI / TDesign 等组件库的主题变量或主题方案）；重命名或替换全局自定义类名与 CSS 变量；统一新色系、字体、圆角、阴影等；浮动 AI 助手、弹窗、设置页等统一采用新主题。
- **验收标准**：视觉上无法通过色值、字体、组件风格与旧版对应；无遗留旧类名/旧变量在首屏或主要流程暴露。
- **涉及端/模块**：`style.css`、`App.vue` 的 style、各组件内样式与第三方 CSS 引用；Naive/TDesign 主题配置。

### 5.4 全局与公共组件

- **描述**：浮动 AI 助手（FloatingAiAssistant）、各类弹窗、设置页、关于页等统一纳入布局与主题改版，风格与主框架一致。
- **验收标准**：与主框架同一套主题变量与布局语言。
- **涉及端/模块**：`FloatingAiAssistant.vue`、使用 NModal/NDialog 的组件、`settings.vue`、`about.vue` 等。
