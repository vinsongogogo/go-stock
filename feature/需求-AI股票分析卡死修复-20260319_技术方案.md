# 技术方案：AI股票分析卡死修复

## 1. 需求依据

- **需求文档**：`/Users/daxue_1/ai-workspace/go-stock/feature/需求-AI股票分析卡死修复-20260319.md`
- **核心需求点**：
  1. AI股票分析页面打开后应在 2 秒内可交互，无冻屏
  2. 初始化只加载用户的自选股（通常 10-50 只），而非全市场股票（5000+）
  3. 并发请求需加分批控制，避免大量并发导致的性能问题

## 4. 技术设计

### 4.1 方案概述

1. **数据源修正**：将 `GetStockList('')` 改为 `GetFollowList(0)` 获取全部自选股
2. **分批加载**：并发 `GetAIResponseResult` 改为分批串行（每批 5 个）
3. **状态批量更新**：收集批次结果后统一更新状态，减少重渲染次数

#### 4.2.2 分批加载历史结果

**当前代码（第 381-399 行）：**

```typescript
// 批量加载历史结果 - 问题：5000+ 并发请求
(stocks || []).forEach(stock => {
  GetAIResponseResult(stock.ts_code).then(result => {
    if (result && result.content) {
      const { structured, markdown } = parseStructuredData(result.content);
      setStockAnalysisList(prev => prev.map(item =>
        item.stockCode === stock.ts_code ? {
          ...item,
          historyResult: result,
          structuredData: structured,
          markdownContent: markdown,
          content: result.content,
          updatedAt: result.CreatedAt ? new Date(result.CreatedAt).toLocaleString('zh-CN') : '',
          phase: 'completed' as AnalysisPhase,
        } : item
      ));
    }
  }).catch(() => {});
});
```

**修改后代码：**

```typescript
// 分批加载历史结果 - 每批 5 个，串行执行批次
const BATCH_SIZE = 5;
const stocksToLoad = stocks || [];

// 定义分批加载函数
const loadHistoryInBatches = async () => {
  const results: Map<string, {
    result: any;
    structured: StructuredAnalysisData | null;
    markdown: string;
  }> = new Map();

  for (let i = 0; i < stocksToLoad.length; i += BATCH_SIZE) {
    const batch = stocksToLoad.slice(i, i + BATCH_SIZE);
    
    // 并行处理当前批次
    const batchPromises = batch.map(async (stock) => {
      try {
        const result = await GetAIResponseResult(stock.ts_code);
        if (result && result.content) {
          const { structured, markdown } = parseStructuredData(result.content);
          results.set(stock.ts_code, { result, structured, markdown });
        }
      } catch {
        // 忽略单个请求错误
      }
    });

    await Promise.all(batchPromises);

    // 每批完成后批量更新状态（减少重渲染次数）
    if (results.size > 0) {
      setStockAnalysisList(prev => prev.map(item => {
        const data = results.get(item.stockCode);
        if (data) {
          return {
            ...item,
            historyResult: data.result,
            structuredData: data.structured,
            markdownContent: data.markdown,
            content: data.result.content,
            updatedAt: data.result.CreatedAt 
              ? new Date(data.result.CreatedAt).toLocaleString('zh-CN') 
              : '',
            phase: 'completed' as AnalysisPhase,
          };
        }
        return item;
      }));
    }
  }
};

// 异步执行分批加载（不阻塞初始渲染）
loadHistoryInBatches();
```

**说明**：
- `BATCH_SIZE = 5`：每批 5 个请求并行
- 批次之间串行执行，避免过多并发
- 每批完成后统一更新状态，减少重渲染次数
- 使用 `Map` 收集结果，避免闭包问题

#### 4.2.3 状态更新优化

上述分批加载方案已包含状态批量更新优化：
- 将原来每个请求返回都触发 `setStockAnalysisList` 改为每批完成后统一更新
- 减少 React 重渲染次数：从 N 次降为 ceil(N/5) 次

## 9. 风险与降级

| 风险 | 可能性 | 影响 | 应对措施 |
|------|--------|------|----------|
| GetFollowList 返回数据格式不兼容 | 低 | 页面无法显示股票列表 | 已确认 FollowedStock 包含 StockCode、Name 字段，转换逻辑已设计 |
| 分批加载导致加载时间变长 | 低 | 历史结果显示慢于预期 | BATCH_SIZE=5 已平衡并发与性能，可根据实测调整 |
| 用户自选股数量异常多（>200） | 极低 | 可能仍有轻微卡顿 | 当前方案可应对，后续可考虑虚拟化列表 |

### 降级方案

如果修复后仍有性能问题：
1. **减小批次大小**：将 `BATCH_SIZE` 从 5 降为 3
2. **延迟加载历史**：初始化时不加载历史结果，用户点击展开时再加载
3. **虚拟化列表**：引入 react-window 只渲染可视区域的卡片
