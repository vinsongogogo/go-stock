# 需求：页面状态保持与后台任务持续

## 需求背景

当前 go-stock React 前端采用条件渲染（`currentView === 'xxx' && <Component />`）实现页面路由切换。当用户切换页面时，旧页面组件被 **完全卸载销毁**，导致：
1. 页面内所有 `useState` 本地状态丢失（如 AIAnalysis 的分析内容、Watchlist 的搜索结果、StockFilter 的筛选条件等）
2. 正在执行的异步任务（如 AI 流式分析）被中断
3. Wails 事件监听（EventsOn）在 useEffect 清理中被注销，后端推送数据丢失
4. 重新进入页面时需要重新加载所有数据，体验不连贯

## 用户原始需求

> 当前页面切换之后，之前的数据就全没了。需求：切换页面之后，之前的动作都还在，页面切回来，任务还在继续执行。

## 澄清后需求明细

### 核心需求：页面组件 Keep-Alive

页面切换时，**不销毁**已加载的页面组件，而是隐藏（CSS display:none 或类似机制），使得：

1. **状态保持**：所有页面的本地状态（useState、useRef）在切换后保持不变
   - AIAnalysis：分析内容、选中的股票、分析配置、历史记录列表
   - Watchlist：股票列表、搜索结果、表单输入
   - StockFilter：已选筛选条件、筛选结果、分页位置
   - Settings：表单输入（未保存的修改）
   - Dashboard：新闻列表、市场数据
   - MoneyFlow：资金流向数据
   - AboutUs：无特殊状态需求

2. **后台任务持续**：进行中的异步操作不因页面切换而中断
   - AI 流式分析（newChatStream 事件监听）在切换到其他页面后**继续接收数据**
   - 实时价格更新（stock_price 事件监听）在 Watchlist 页不可见时**继续接收**
   - 新闻推送（newTelegraph、newSinaNews 等事件监听）**持续活跃**

3. **切回恢复**：用户切回页面时，看到的是最新的实时状态
   - AI 分析若已完成，切回后直接看到完整结果
   - AI 分析若仍在进行，切回后看到当前进度并继续实时更新
   - Watchlist 价格已同步到最新
   - 新闻列表已包含切走期间的新推送

### 影响范围

| 页面组件 | 需要保持状态 | 有后台任务 | 优先级 |
|---------|:-----------:|:---------:|:-----:|
| AIAnalysis | ✅ | ✅（流式分析） | 高 |
| Watchlist | ✅ | ✅（实时价格） | 高 |
| Dashboard（含 NewsFeed/MarketGauge/TreeMap） | ✅ | ✅（新闻推送） | 高 |
| StockFilter | ✅ | ❌ | 中 |
| Settings | ✅ | ❌ | 中 |
| MoneyFlow | ✅ | ❌ | 中 |
| AboutUs | ❌（静态） | ❌ | 低 |

### 非功能需求

1. **性能**：所有页面常驻不会导致明显内存增长或渲染卡顿（当前共 7 个页面，规模可控）
2. **兼容性**：不改变现有后端 API 和 Wails 事件通信协议
3. **最小改动原则**：优先在 App.tsx 层面解决，避免大范围重构各页面组件内部逻辑

### 技术约束

- 当前框架：React + Wails（无 React Router 实际使用）
- 路由机制：App.tsx 中 useState(`currentView`) + 条件渲染
- 事件系统：Wails EventsOn/EventsOff
- 无全局状态管理库

（无）

## 验收标准

1. 在 AIAnalysis 页面发起一次流式分析 → 分析过程中切换到 Watchlist → 等待若干秒 → 切回 AIAnalysis → 分析内容已更新（或已完成），不丢失
2. 在 StockFilter 页面设置若干筛选条件并执行筛选 → 切换到 Settings → 切回 StockFilter → 筛选条件和结果仍在
3. 在 Settings 页面修改但不保存 → 切换到其他页面 → 切回 Settings → 修改内容仍在
4. Watchlist 页面的实时价格在切走期间持续更新，切回后显示最新价格
5. Dashboard 新闻在切走期间持续接收，切回后看到切走期间的新消息
